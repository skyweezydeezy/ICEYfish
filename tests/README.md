# Tests

Scenario tests for the simulation engine (`goldfish/static/sim.js`). They use a saved copy of the Frodo/Sam commander deck
(`fixtures/frodo-loaded.json` and `fixtures/veyran-loaded.json` and `fixtures/second-breakfast-loaded.json` and `fixtures/loyalty-program-loaded.json` and `fixtures/zul-ashur-loaded.json` and `fixtures/death-tax-loaded.json`, and others, real Scryfall data) so they run offline.

```
node tests/run.js          # engine tests: no network; the files run side by side, one per processor (about 4 minutes on 4 processors)
node tests/run.js pod rules-batch29   # only the files whose names contain one of these;  --jobs 2 chooses how many at a time
node tests/run.js --ui     # browser tests: needs `npm i playwright`, a Chromium, and internet (Scryfall); starts its own static server on :8800
python tests/launch/test_launch.py   # launch tests: the self-updater and the local server; no internet (a local server plays GitHub)
```

Test files run side by side: one per processor core for the engine tests, 3 at a time for the browser tests. `--jobs N` sets the number
(`--jobs 1` = one after another). Name files to run only those: `node tests/run.js --ui viewer cardview`. GitHub runs the engine tests on
every pull request and every push to a work branch (`.github/workflows/tests.yml`), so before asking for a merge a session only needs to
run the tests for what it changed and wait for the green check.

Browser tests (T-110): `run.js --ui` preloads `tests/ui-fetch-cache.js` into every test. The tests answer the page's Scryfall requests with Node's
fetch; the preload keeps each successful Scryfall answer on disk (`$TMPDIR/isf-scryfall-cache`, or `ISF_SCRY_CACHE`) and retries errors, 429 and 5xx,
so a cold cache or a busy proxy no longer times out the later tests of a long run (`ISF_NO_SCRY_CACHE=1` turns it off). Running a test file by hand
(`node tests/ui/x.ui.js`) with the server on :8800 does not use the cache unless you add `NODE_OPTIONS="--require ./tests/ui-fetch-cache.js"`.
Click `#tAutoTo` at `{ position: { x: 12, y: 12 } }`: its middle is the turn number box, which does nothing.

The played 1v1 and Pod games have their own two files: `engine/decisions.test.js` (one scenario per decision point, and the proof that a
played game with every default taken is the autopilot's game) and `ui/decisions.ui.js` (the same decision points in the browser).

Each file builds a small board (for example Sorin plus three Soldiers), triggers one rule and checks the result, then plays 400-600 full
games to make sure nothing throws. Add a new `tests/engine/<feature>.test.js` for every card or rule you add to the engine.
