# T-137: fastest-win replay (TASK note)

What it is: each built-in deck's fastest real 1v1 Duel win against one standard opponent, shown on the Build tab ("Fastest win vs Second Draw: turn N · about 1 game in R", ▶ Watch, 🔍 Find) and replayed on the Duel tab from the dice roll.

- **Data**: `goldfish/static/decks/fastest.json`, made by `node tools/fastest-kill.js` (about 42 minutes on 4 threads for 55 decks; `--only=<file>` for one deck). Shared Node code: `tools/lib/fastest.js` (DUEL_OPTS must equal REPLAY_OPTS in versus.js).
- **Standard opponent**: Second Draw (Alandra), Bracket 3, median kill T8. Chosen by measuring 7 Bracket 3 candidates (median T8+) in 100 Duels: it was the only one whose games showed blocks, counterspells and removal (per won game 2.1 / 0.4 / 1.0). Fallback for itself: Dead Ringers.
- **Two stages**: 20,000 goldfish games per deck rank the seeds (on the draw, up to 7 turns), then the best 200 seeds are Duelled once with each seat first (400 Duels). Ties on turn go to the win where the opponent fought back most. Rarity = how many of the 20,000 goldfish games kill by that turn.
- **Per-player streams**: already true in the engine (seat i is seeded `seed + i * 0x9e3779b9` and only its own shuffles use it), so seat 0's opening hand depends only on the seed. `tests/engine/fastest-duel.test.js` checks it.
- **Find (any deck)**: the same two stages, smaller (1,500 goldfish games, best 30 seeds x 2), run on the page; result kept per deck in localStorage `isf_fastest`, ignored after an app version change.
- **Rules bugs found by the first run** (Mox Amber, Monolith + Rings startup mana, Breach win) were fixed by T-140 (v238); the data was re-run on v238.
